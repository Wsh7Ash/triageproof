# Signature Recomputation

> Recompute the signature from the saved stack before publishing, because a hand-typed signature is the most common way a duplicate gets filed twice

**Use when:** any record that contains a signature field

**Avoid when:** the signature is generated by a platform you cannot re-run, which needs its algorithm recorded

## Procedure

1. Save the stack file the signature was derived from.
2. Recompute the signature with the recorded depth and kind.
3. Compare with the value in the record.
4. On mismatch, fix the record rather than the stack.
5. Record the tool version and depth used for the computation.
6. Re-run after any parser or noise-list change.

## Signals

- The signature in the report does not appear anywhere in the artifacts.
- Two reports of the same bug carry different signatures.
- The recorded signature changes after a parser update.
- The signature was copied from a platform that uses a different algorithm.

## Patterns

**1. Recompute**

```text
triageproof signature evidence/stack/frames.txt --kind heap-use-after-free  -> the value to store
```

**2. Mismatch is blocking**

```text
declared != computed -> the record cannot be submitted
```

**3. Version pin**

```text
record parser version with the signature  -> explains future drift
```

## Pitfalls

- Typing a signature by hand and transposing a character.
- Copying a platform signature without recording which algorithm produced it.
- Recomputing after a parser change without re-baselining the cluster set.

## Done when

- The declared signature equals one recomputed from the saved stack.
- The depth, kind and tool version are recorded with it.
